# 审查压缩——实证数据

2026-05-31

---

## 摘要

设计文档（*Review scaling and complexity* 一节）声称每项的审查面
"通常约为代码面的 10%"。本文档呈现了来自 liyi 代码库自身的实证
测量——一项自参照数据：工具自身的代码已被完整标注了意图规格。

**核心结论：审查者只需阅读约 515 行意图描述，即可替代阅读约 15,682
行源代码——审查面缩减 30.5 倍。** 纯意图文本仅占源代码行数的 3.3%。

但这一汇总数字掩盖了一个更有意思的发现。绝大多数代码在审查时会被
*压缩*，但有两类却出现了*膨胀*：GitHub Actions 工作流与 `schema.rs`
产出的意图文本比源代码还长。这反直觉却很重要——参见
[审查膨胀](#审查膨胀当意图超过源代码)。

---

## 方法论

由测量脚本 `scripts/measure-intent-ratio.py` 遍历代码库并收集以下
数据：

1. **源文件** — 所有生产环境源文件（`.rs`，以及 `.yml` GitHub
   Actions 工作流和其他受支持语言），排除 `tests/` 和 `fixtures/`
   目录。
2. **伴生规格文件** — 与上述源文件同目录的所有 `.liyi.jsonc` 文件。
3. **规格内容** — 从 JSONC 伴生文件中解析：条目名称、`intent` 文本、
   `=doc` / `=trivial` 标记、`reviewed` 状态。

报告中包含三个层级的压缩指标：

| 层级 | 含义 | 包含内容 |
|---|---|---|
| **完整伴生文件**（行/字节比） | 规格文件总量与源代码之比 | JSON 样板、哈希值、行号范围、意图文本 |
| **字节比** | 伴生文件与源代码的原始字节之比 | 同上，按字节度量 |
| **纯意图文本** | 仅自然语言意图字符串 | 仅 `"intent"` 字段值，不含 JSON 结构 |

纯意图文本层级是审查者实际需要阅读的内容。JSON 元数据
（`source_span`、`source_hash`、`tree_path` 等）由检查工具消费，
审查者无需阅读。

## 结果（2026-05-31 快照）

### 汇总指标

| 指标 | 值 |
|---|---|
| 生产源文件数 | 53 |
| 伴生规格文件数 | 49 |
| 源代码行数 | 15,682 |
| 源代码字节数 | 527,906 |
| 伴生文件行数（完整 JSON） | 3,813 |
| 伴生文件字节数 | 171,592 |
| **完整伴生文件 / 源代码（行）** | **24.3%** |
| **完整伴生文件 / 源代码（字节）** | **32.5%** |

### 规格内容分析

| 指标 | 值 |
|---|---|
| 总条目规格数 | 173 |
| 描述性意图 | 148 |
| `=doc` 标记 | 17 |
| `=trivial` 标记 | 8 |
| 已审查（人工确认） | 173（100%） |
| 意图文本总字符数 | 41,194 |
| 平均意图长度 | 278 字符（约 3.5 行） |
| 每条规格对应的平均源代码行数 | 90.6 |

### 审查压缩

| 指标 | 值 |
|---|---|
| 纯意图文本（按 80 字符/行估算行数） | 约 515 |
| **意图文本 / 源代码行数** | **3.3%** |
| **意图文本 / 源代码字节数** | **7.8%** |
| **缩减倍数** | **30.5×** |

### 按模块统计

| 模块 | 源代码行数 | 规格行数 | 伴生文件比例 |
|---|---|---|---|
| liyi（核心） | 5,828 | 1,541 | 26.4% |
| liyi-cli | 1,250 | 296 | 23.7% |
| liyi::tree\_path | 7,183 | 1,209 | 16.8% |
| GHA 工作流 | 202 | 266 | 131.7% |

### 特殊情况

- **tree\_path/mod.rs** — 伴生文件比例为 13.2%（2,220 行源代码，294
  行规格）。最大的模块压缩效果最好，因为其大量体积是 match 分支
  与语法样板，由少数行为规格覆盖。
- **lang_go.rs** — 比例为 9.5%（328 行源代码，31 行规格），压缩最
  佳：一个语言语法适配器，一条意图规格即可涵盖一长串机械化的
  结构映射。
- **schema.rs** — 比例为 147.8%（23 行源代码，34 行规格）。这是
  *膨胀*，而非压缩——参见下文。
- **GHA 工作流** — 124.7%（`ci.yml`）与 135.7%（`release.yml`）。
  同样是膨胀——参见下文。

## 解读

设计文档声称每项的审查成本"约为代码面的 10%"。本次测量得出两个互补
结论：

1. **完整伴生文件比例约 24%** — 包含审查者无需阅读的结构化元数据在内
   的完整 JSON 伴生文件约为源代码的四分之一。这是上界。

2. **纯意图文本约 3.3%** — 审查者实际阅读的自然语言文本不到源代码的
   4%。这是审查面的下界。

设计文档中的"约 10%"落在上下界之间，合理的解释是：该估计涵盖了阅读
意图文本以及浏览结构性上下文（条目名称、行号范围）的成本，但不包括
完整 JSON 元数据。

30.5 倍的压缩因子特定于当前快照下的本代码库。不同代码库的差异：

- 结构重复性高的代码库（语言语法、CRUD 端点、生成的适配器）压缩率
  **更高**。
- 密集且各异的业务逻辑代码库（每个函数都需要详细行为规格）压缩率
  **更低**。

`tree_path` 模块（伴生文件比例 16.8%）展示了结构重复场景：20 个
语言特定文件共享同一结构模式，每种语言的一条意图规格即可覆盖数百行
 match 分支。

## 审查膨胀：当意图超过源代码

汇总压缩数字令人安心，但逐文件表格揭示了两类意图文本反而**长于**其
描述的源代码的情况：

| 文件 | 源代码行数 | 规格行数 | 比例 |
|---|---|---|---|
| `.github/workflows/release.yml` | 129 | 175 | 135.7% |
| `.github/workflows/ci.yml` | 73 | 91 | 124.7% |
| `crates/liyi/src/schema.rs` | 23 | 34 | 147.8% |

起初这被当作无关紧要的边界情况一笔带过（"规格元数据超过了极小的源
文件"）。但仔细审视后，它揭示的是更根本的东西，并且颗覆了人们对意图
规格何处收益最大的直觉。

**绝大多数代码是某个形式系统的翻译。** 解析器将语法映射为 AST；哈希
例程实现某个具名的摘要算法；密集 match 的分发枚举的是类型中已然拼写
出来的情况。对于这类代码，源代码*就是*规格——阅读它几乎就能知道它应
该做什么。意图文本只需捕捉形式系统遗留的那层薄薄的隐含残余，因此压缩
得很厉害（`tree_path` 语法适配器达到 9～16%）。

**契约型与运维重型的代码则恰恰相反。** 以 CI 工作流为例，源代码是
简洁的声明式 YAML：

```yaml
permissions:
  contents: read
```

这两行承载着一整套*不存在*于源代码中的安全论证——最小权限原则、
本工作流中没有任何作业需要写权限这一事实，以及该假设一旦改变的后果。
意图规格必须把这些全部说出来：

> 将 GITHUB_TOKEN 限制为只读内容访问（最小权限原则）。本工作流中
> 没有作业需要写权限。

同样的模式贯穿整个工作流："必须跳过 tag ref，以免没有 DCO 文本的
发布 tag 导致 CI 失败"、"用 `-D warnings` 使任何 lint 触发硬失败"、
"必须不就地重新格式化——仅检查"。每一条都是 YAML 无法表达的*为何*或
*不得*。形式产物是一份配置；使其正确的知识是隐含的，而意图规格是
唯一记录它的地方。

`schema.rs` 出于同样的原因而膨胀。`validate_version` 是六行简单的
字符串比较，但其意图是一份契约：只接受 `"0.1"`，拒绝其余一切，并与
系统其余部分所依赖的版本字段保持耦合。源代码三秒内就能看出它*做了
什么*；规格记录的是它*必须继续做什么*及其原因——这恰恰是审查者需
要的部分，也是重构最可能破坏的部分。

**这个教训颗覆了天真的成本模型。** 人们可能假设意图规格对大型复杂函
数最有价值，对极小的声明式函数则是浪费。数据在*每行审查价值*上说的
恰恰相反：膨胀率最高的条目是最小的源文件，因为它们的正确性几乎完全
依赖于隐含知识——安全姿态、运维不变量、版本契约——而这些是形式产
物有意省略的。对这类代码而言，伴生文件不是源代码的压缩复述；它是推
理过程的*唯一*书面记录，阅读这些文本严格比阅读 YAML 更有信息量。

因此，膨胀并非需要优化掉的缺陷。它是一个信号，表明某个文件的真正复
杂度位于其源代码文本之外——恰恰是那些跳过规格会最危险的文件。
## 如何复现

```sh
python3 scripts/measure-intent-ratio.py [ROOT]
```

在代码库根目录运行（或将 `.` 作为 ROOT 传入）。仅需 Python 3.10+
及标准库。
